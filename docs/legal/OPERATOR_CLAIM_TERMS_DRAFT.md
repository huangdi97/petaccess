# OPERATOR_CLAIM_TERMS_DRAFT.md

> **`LEGAL_REVIEW_REQUIRED`** — 工程侧草案，未经执业律师审阅，不得对外发布。
> 对应能力：`apps/admin` `ClaimsView`、后端 operator/claim 接口、`PolicyTemplate` / `PlacePolicyBinding`。

## 1. 什么是「认领」

场所的管理方（或其授权代表）可申请认领该场所，从而：
- 提交本场所的官方宠物准入政策；
- 按区域（Zone）设置差异化规则；
- 发布临时政策（活动、装修、季节调整）；
- 提交设施、出入口、通行路径等信息；
- 对与其场所相关的纠错进行处理。

## 2. 认领需提供

1. 主体信息：单位全称、统一社会信用代码 `[待律师确认是否必需]`；
2. 授权证明：能证明申请人对该场所有管理权的材料；
3. 联系人信息与联系方式；
4. 拟提交的政策文本及其官方出处（官网链接/公告编号/现场告示照片）。

## 3. 认领后的权利边界（重要）

管理方**可以**：
- 在 `OPERATOR_POLICY` 层提交与更新本场所规则；
- 申请修正错误收录的本场所信息。

管理方**不可以**：
- 覆盖或删除 `LEGAL` 层的法定规则；
- 删除用户提交的现场观察记录（观察与政策并存展示）；
- 要求平台删除与用户投诉相关的内容，除非该内容本身不实或侵权；
- 要求平台给予评分、排名或推荐位（平台不提供此类功能）。

## 4. 冲突处理

| 情形 | 处理 |
|---|---|
| 管理方政策与法定规则冲突 | 保留法定结论；标注层级张力；不删除任一方来源 |
| 管理方政策与用户观察不符 | 两者并存；政策层参与规则解析，观察层仅作参考 |
| 多个主体声称同一场所管理权 | 暂停认领，人工核实后裁定 |
| 管理方要求删除历史版本 | 拒绝；历史版本是证据链的一部分，仅做标记 |

## 5. 认证与撤销

- 认证通过后，管理方提交的内容标注为「管理方确认」；
- 若主体资格存疑、信息失实或滥用，平台可暂停或撤销认领权限；
- 撤销后，此前以管理方身份提交的规则**保留**（作为历史来源），但不再更新。

## 6. 责任

管理方对其提交内容的真实性、合法性负责。因提交不实内容造成第三方损害的，由提交方承担责任。`[待律师确认]`
