## 1. 我们回答什么

三个问题：

1. **能不能进** —— 我的宠物可以进入吗？
2. **进到哪里** —— 场所内哪些区域可以、哪些不可以？
3. **凭什么** —— 这个结论来自哪个来源、什么时候核验的？

**我们不回答**：这家店好不好、文明不文明、值不值得去。

## 2. 规则从哪里来

| 来源层级 | 说明 | 前台标签 |
|---|---|---|
| `LEGAL` | 法律法规、条例 | 官方法规 |
| `REGULATORY_GUIDANCE` | 主管部门指导意见 | 政府来源 |
| `OPERATOR_POLICY` | 场所管理方政策 | 管理方确认 |
| `TEMPORARY_POLICY` | 试点、活动、临时政策 | 管理方确认 |

来源按证据获取方式分级（**描述性分类，不是可信度评分**）：
`primary_direct`（官方/政府页面直抓）· `primary_captured`（现场采集）· `secondary_reputable`（可靠媒体/平台转述）· `search_snippet`（搜索引擎摘要）· `user_submitted`（用户提交）· `social_lead`（社媒线索）。

**弱证据永不发布**：`search_snippet` 与 `social_lead` 的候选在发布边界被硬性拦截，必须先完成证据补强。

## 3. 一条规则要经过什么才能上线

```
发现 → 提取 → 匹配场所 → 人工审核 → 发布前六检 → 发布
```

**发布前六检**（任一失败即拒绝，永不静默降级）：
1. 证据可追溯（有原文片段或内容哈希）
2. 场所归属（有 place_match 证据）
3. schema 支持（字段合法、区域属于该场所）
4. 无未解决冲突（跨来源相反效果必须人工解决）
5. 时效（证据在核验周期内）
6. 数据许可（lead-only / 不可存储证据不得发布）

**AI 的角色**：AI 只做提取与候选生成，**不做规则裁决**。每条规则的最终批准由具名人类评审员签署。

## 4. 状态的含义

| 状态 | 含义 |
|---|---|
| **明确允许** | 已核验来源明确允许 |
| **有条件** | 满足所列条件后方可进入（如牵引、疫苗、数量上限） |
| **明确限制** | 已核验来源明确限制 |
| **尚未核验** | 在已核验来源中暂未找到明确规则。**这不代表允许。** |
| **来源存在不一致** | 已收录来源之间结论冲突，待人工复核 |
| **需要复核** | 证据超出核验时效，结论可能已变化 |

## 5. 我们如何处理法规与场所政策的张力

现实中的规则常常冲突。例如某条例禁止犬只进入餐饮场所，而某品牌推行宠物友好计划。

我们的处理方式：
- **分层建模**：法定规则与运营方规则分属不同层级，各自保留来源；
- **例外显式化**：法条中的豁免（如导盲犬）作为该条规则的**例外**建模，而不是另立一条可能与之冲突的规则；
- **不猜测**：无法判断时输出「来源存在不一致」或「尚未核验」，绝不取一个"看起来合理"的答案；
- **留痕**：所有变更进入审计日志。

## 6. 我们不做什么

- 不提供评分、排名、红黑榜；
- 不计算"遇宠率"；
- 不默认长期保存用户位置轨迹；
- 不把「尚未核验」显示为「允许」；
- 不把用户现场观察当作场所政策；
- 不把 AI 的判断当作最终规则。
