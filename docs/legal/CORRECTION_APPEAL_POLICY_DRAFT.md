## 1. 适用对象

- **用户**：认为某条规则有误、已变化或不完整；
- **场所管理方**：认为其场所的规则被错误收录；
- **任何主体**：认为内容侵犯其合法权益。

## 3. 处理流程（目标）

```
提交 → 自动归类 → 人工初审（SLA: T+1 工作日）
     → 需补证 → 通知提交人
     → 成立   → 修正规则 / 撤回 / 标记「来源存在不一致」
     → 不成立 → 说明理由
→ 结果通知 → 可申诉一次
```

## 4. 时效承诺（目标值，尚未验证）

| 环节 | 目标 |
|---|---|
| 初审响应 | 1 个工作日 |
| 需补证的通知 | 2 个工作日 |
| 规则修正生效 | 5 个工作日 |
| 场所方申诉复核 | 5 个工作日 |

> 该 SLA 尚未经过真实运营验证，属**目标值**。

## 5. 处理原则

1. **来源优先**：判断依据是来源，不是提交量或声量。
2. **不因投诉删除事实**：仅当来源不成立或规则已变更时才修改；对"不喜欢这个结论"的投诉不予受理，但会记录。
3. **留痕**：每次变更进入审计日志，保留前后状态。
4. **不猜测**：无法判定时标记「来源存在不一致」，不擅自取舍。
5. **撤回机制**：规则被撤回后不再参与解析，历史版本保留。

## 6. 场所管理方的特殊权利

- 管理方可通过认领流程提交**官方政策**，其内容按 `OPERATOR_POLICY` 层收录；
- 管理方政策**不能覆盖法定禁止**：若与 `LEGAL` 层冲突，平台保留法定结论并标注张力；
- 管理方不得要求删除与其政策不符的用户现场观察记录（观察 ≠ 政策，两者并存展示）。

## 7. 恶意投诉

对反复提交明知不实内容的账号，平台可限制其贡献权限。
