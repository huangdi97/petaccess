## 1. 事故分级

| 级别 | 定义 | 响应 | 示例 |
|---|---|---|---|
| **S1** | 已发布规则错误，可能误导用户 | 立即响应 | 某场所被错误标注为「明确允许」而实际禁止 |
| **S2** | 数据丢失或泄露 | 立即响应 | 数据库损坏、备份失效、未授权访问 |
| **S3** | 服务不可用 | 小时级 | API 5xx、地图 provider 长时间故障 |
| **S4** | 单点功能异常 | 工作日 | 某个 Admin 页面报错 |

## 2. S1 — 已发布规则错误

**黄金法则：先撤回，后调查。** 宁可短暂显示「尚未核验」，也不显示错误结论。

```
1. 撤回受影响规则（ROLLBACK_RUNBOOK §2）
2. 验证 effective-rules 不再返回该规则，且回落为 UNKNOWN（不是 allowed）
3. 在 audit_log 标注事故编号
4. 追溯：该规则如何通过六检？是证据问题、归因问题还是 schema 问题？
5. 若为系统性问题 → 暂停同类发布，修复后再开
6. 生成复盘：受影响场所、时间窗、影响面
```

**影响面判定**：查询该规则的 `place_id`/`zone_id`，结合请求日志统计受影响查询量。

## 3. S2 — 数据丢失或泄露

### 3.1 数据丢失

```
1. 停止写入（停 API + worker）
2. 评估范围：哪些表、哪个时间点
3. 从最近备份恢复（BACKUP_RESTORE_RUNBOOK）
4. 校验：alembic 版本、审计连续性、PostGIS 可用、行数对账
5. 恢复服务 + smoke
```

### 3.2 个人信息泄露

```
1. 立即止损：吊销受影响凭据、封堵入口
2. 判定范围：哪些个人数据、多少主体
3. 保留证据（勿删除日志）
4. 依法评估是否需要向监管与个人告知（时限要求由律师确认）
5. 修复根因 + 复盘
```

> **法定义务时限**：个人信息泄露的通知义务与时限**须由律师确认**（`LEGAL_REVIEW_REQUIRED`）。本手册不提供法律结论。

## 4. S3 — 服务不可用

| 组件故障 | 降级动作 |
|---|---|
| 地图 provider | `MAP_PROVIDER=mock`，前端显示「地图暂不可用，可用列表浏览」 |
| AI/OCR provider | `AI_PROVIDER=mock`，贡献入口提示「识别暂不可用，请手动填写」 |
| Redis | 任务队列暂停；只读查询继续；限流退化为进程内计数 |
| MinIO/S3 | 上传暂停；已有证据读取不受影响 |
| worker | 监控/抽取任务积压；接口可用性不受影响 |
| DB | **无降级**——直接 503，优先恢复 |

|---|---|
| 结构化日志 | ✅ `app/core/observability.py` |

**结论**：事故检测当前依赖人工巡检与健康检查，**不满足生产的主动告警要求**。这是 P8 的缺口（见 `FINAL_PRODUCTION_READINESS_REPORT.md`）。

## 6. 复盘模板

```markdown

- 影响面：场所数 / 查询数 / 用户数
- 时间线（发现 → 止损 → 恢复）

- 修复项（含负责角色与验证方式）
- 需更新的文档 / 测试 / 门禁
```
